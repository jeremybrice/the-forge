### Task 1: Add `action_items` to the task harvester command template

**Files:**
- Modify: `slack-forge/agents/forge-task-harvester.md:33-44`

**Context:** The `## Harvest Creation` command template (lines 33-44) is missing `action_items` from the `--data` JSON, but the `## Content Quality Requirements` section (line 64) and anti-patterns (line 71) both mandate it. The field is a `_TEMPLATE_ONLY_FIELD` in `harvest_ops.py` — it routes through `--data` and the template renders it under `## Action Items`.

**Step 1: Add `action_items` to the command template**

In `slack-forge/agents/forge-task-harvester.md`, replace the `## Harvest Creation` code block (lines 32-45) with:

````markdown
```bash
forge harvest create "{task_title}" --harvest-type task --data '{
  "source_channel": "{channel_name}",
  "source_channel_id": "{channel_id}",
  "source_author": "{author}",
  "source_timestamp": "{timestamp}",
  "scan_timeframe": "{timeframe}",
  "scan_date": "{scan_date}",
  "confidence": "{high|medium|low}",
  "tags": ["{tag1}", "{tag2}"],
  "content": "{extracted task summary}",
  "source_context": "{supporting quote/context}",
  "action_items": ["{verb + responsible person + deliverable}"]
}'
```
````

This adds `"action_items"` as the last field before the closing `}'`, consistent with the quality requirement on line 64 that says each item must start with a verb and name a responsible person.

Expected: 3 hits — the command template (line ~43), the quality description (line ~65), and the anti-pattern (line ~72). All three now agree that `action_items` is required and the template shows how to pass it.

### Task 2: Fix digest content structure ordering to lead with actionable items

**Files:**
- Modify: `slack-forge/agents/forge-jira-digest.md:47-61`

**Context:** Three sources currently conflict on ordering:
- `forge-jira-digest.md` line 51: Summary Stats is step 1
- `forge-jira-digest.md` line 55: "Lead with this section" on step 2 (Items Needing Action)
- `forge-jira-digest.md` line 77 (Rules): "Lead with items needing action"
- `slack-forge/skills/jira-digest/SKILL.md` line 59: "Lead with actionable items" as step 1

The fix: Reorder so "Items Needing Action" is step 1, "Summary Stats" becomes step 2. This aligns the structure with both the SKILL.md and the agent's own Rules section.

**Step 1: Reorder the Digest Content Structure section**

In `slack-forge/agents/forge-jira-digest.md`, replace lines 47-61 with:

```markdown
## Digest Content Structure

The `content` field is an executive briefing. It must follow this fixed structure:

### 1. Items Needing Action
One paragraph per actionable item (`needs_action: true`). Each paragraph must explain: which ticket, what happened, and why the user should care. This is the most important section — lead with it.

### 2. Summary Stats
A single bolded stats line: **X unique tickets** referenced across **Y events** — broken down by type (status transitions, comments, new issues, assignments).

### 3. Status Transitions
Group by outcome: **To Done** (completed work), **Fix Required to In Progress** (rework), **To Do to In Progress** (work started). Use bullet lists with ticket ID, summary, and assignee.

### 4. Key Tickets to Watch
3-5 strategically important tickets with a sentence of business context each. These are tickets that have cross-team impact, external dependencies, or product decisions pending.
```

Key changes:
- "Items Needing Action" is now step 1 (was step 2)
- "Summary Stats" is now step 2 (was step 1)
- Removed "Lead with this section" from the Items Needing Action paragraph since it is now first and leading is implicit
- Changed to "This is the most important section — lead with it" for clarity

**Step 2: Verify consistency across all three sources**

Expected: All references agree that actionable items come first:
- Agent structure: step 1 = Items Needing Action
- Agent Rules line 77: "Lead with items needing action"
- SKILL.md line 59: "Lead with actionable items"
